# Browser Audit — NURA (2026-06-22)

## Сводка
- Кол-во найденных проблем: 4 критичных / 4 средних / 1 мелкая
- Общее впечатление от UX: маркетинговая часть и PWA выглядят как две разные версии продукта. На проде лендинг уводит в Telegram и живёт по старой воронке, а в текущем фронте заявлен web-first/PWA-сценарий. Из-за этого пользовательские обещания, цены и точки входа расходятся.

## Найденные проблемы

### [КРИТИЧНО] Прод-лендинг ведёт в Telegram вместо текущей web/PWA-воронки
- **Где:** `https://nura-ai.ru/` (живой прод)
- **Шаги воспроизведения:** 1. Открыть главную страницу. 2. Проверить hero CTA, блок тарифов, финальный CTA, ссылки в шапке/футере. 3. Сравнить с текущей спецификацией `docs/launch-checklist.md`, `docs/pwa-spec.md`.
- **Ожидаемое поведение:** основной вход должен вести в web/PWA-воронку (`/mini.html`, `/app/`, web checkout), как описано в текущей документации и локальном фронте.
- **Фактическое поведение:** живой HTML прод-лендинга уводит пользователя в Telegram-бот почти из всех ключевых CTA: hero, тарифы, финальный блок, футер.
- **Скриншот/консольная ошибка (если есть):** live snapshot `https://nura-ai.ru/`, строки `2`, `10`, `111`, `124`, `137`, `148`, `176`, `210`, `216`; локально текущая воронка уже другая: [index.html](/C:/git/NURA/index.html:313), [index.html](/C:/git/NURA/index.html:320), [index.html](/C:/git/NURA/index.html:501), [index.html](/C:/git/NURA/index.html:540)

### [КРИТИЧНО] На проде показывается устаревшая цена полного разбора
- **Где:** `https://nura-ai.ru/`, блок тарифов
- **Шаги воспроизведения:** 1. Открыть лендинг. 2. Дойти до блока “Полный разбор личности”. 3. Сверить цену с локальным фронтом и backend-логикой оплаты.
- **Ожидаемое поведение:** цена и оффер должны совпадать с текущим checkout-флоу.
- **Фактическое поведение:** на живом лендинге показано `990 ₽ 690 ₽`, тогда как в текущем фронте и backend используется `890 ₽`.
- **Скриншот/консольная ошибка (если есть):** live snapshot `https://nura-ai.ru/`, строки `127-137`; текущий фронт: [index.html](/C:/git/NURA/index.html:501), backend: [web.py](/C:/git/NURA/nura_app/api/routes/web.py:145)

### [КРИТИЧНО] PWA offline/service worker сломан на уровне маршрута и кэша
- **Где:** PWA `/app/*`, `mini.html`, `success.html`, service worker
- **Шаги воспроизведения:** 1. Открыть любую PWA-страницу. 2. Дождаться регистрации service worker. 3. Проверить путь SW и поведение без сети.
- **Ожидаемое поведение:** страницы должны регистрировать существующий SW-файл, а SW должен кэшировать хотя бы offline fallback и базовые ассеты.
- **Фактическое поведение:** страницы регистрируют `/service-worker.js`, но фронтовый nginx обслуживает только `/sw.js`. Дополнительно сам [sw.js](/C:/git/NURA/frontend/sw.js:1) не делает precache и не отдаёт `offline.html`, поэтому заявленный офлайн-режим не реализован.
- **Скриншот/консольная ошибка (если есть):** регистрация: [frontend/pwa/app/index.html](/C:/git/NURA/frontend/pwa/app/index.html:9), nginx route: [frontend/nginx.conf](/C:/git/NURA/frontend/nginx.conf:22), SW логика: [frontend/sw.js](/C:/git/NURA/frontend/sw.js:1)

### [КРИТИЧНО] Кнопка подписки в PWA профиле бьёт в тестовый endpoint
- **Где:** `/app/profile`, вкладка “Подписка”
- **Шаги воспроизведения:** 1. Открыть профиль. 2. Нажать “Подключить подписку”. 3. Проверить HTTP endpoint.
- **Ожидаемое поведение:** пользователь должен уходить в реальный checkout `/api/v1/web/subscribe`.
- **Фактическое поведение:** фронт вызывает `/api/v1/web/test-subscribe`, который разрешён только при `test_mode`; в production должен отвечать `403`.
- **Скриншот/консольная ошибка (если есть):** frontend: [frontend/pwa/app/profile.html](/C:/git/NURA/frontend/pwa/app/profile.html:188), production-only guard: [web.py](/C:/git/NURA/nura_app/api/routes/web.py:366), реальный endpoint: [web.py](/C:/git/NURA/nura_app/api/routes/web.py:260)

### [СРЕДНЕ] Переключатели уведомлений стучатся в несуществующий API
- **Где:** `/app/profile`, вкладка “Уведомления”
- **Шаги воспроизведения:** 1. Открыть профиль. 2. Переключить любой toggle уведомлений. 3. Проверить вызов API.
- **Ожидаемое поведение:** настройки должны сохраняться на сервере и влиять на реальные уведомления.
- **Фактическое поведение:** фронт делает `PATCH /api/v1/user/notifications`, но такого маршрута в `nura_app/api/routes` нет. По факту меняется только `localStorage`.
- **Скриншот/консольная ошибка (если есть):** вызов: [frontend/pwa/app/profile.html](/C:/git/NURA/frontend/pwa/app/profile.html:138)

### [СРЕДНЕ] История чата не сохраняет ответы NURA
- **Где:** `/app/chat`
- **Шаги воспроизведения:** 1. Отправить сообщение в чат. 2. Получить ответ NURA. 3. Перезагрузить страницу. 4. Сравнить восстановленную историю.
- **Ожидаемое поведение:** обе стороны диалога должны переживать reload и участвовать в следующем контексте.
- **Фактическое поведение:** в `localStorage` сохраняются только сообщения пользователя; ответы NURA только рисуются в DOM. После reload история неполная, а серверу уходит обрезанный контекст.
- **Скриншот/консольная ошибка (если есть):** восстановление истории: [frontend/pwa/app/chat.html](/C:/git/NURA/frontend/pwa/app/chat.html:71), запись только user: [frontend/pwa/app/chat.html](/C:/git/NURA/frontend/pwa/app/chat.html:99), ответ без `saveMsg`: [frontend/pwa/app/chat.html](/C:/git/NURA/frontend/pwa/app/chat.html:113)

### [СРЕДНЕ] Install UI для PWA фактически не может отрисоваться
- **Где:** `mini.html`, install flow
- **Шаги воспроизведения:** 1. Открыть `mini.html`. 2. Дождаться `beforeinstallprompt` или iOS timeout. 3. Проверить, появляется ли install banner/modal.
- **Ожидаемое поведение:** должен появиться Android banner или iOS modal с инструкцией.
- **Фактическое поведение:** `mini.html` подключает `/pwa-install.js`, но требуемых DOM-элементов `#pwa-install-banner` и `#pwa-ios-modal` в проекте нет вообще, поэтому показывать нечего.
- **Скриншот/консольная ошибка (если есть):** подключение: [mini.html](/C:/git/NURA/mini.html:226), ожидание DOM-элементов: [frontend/pwa-install.js](/C:/git/NURA/frontend/pwa-install.js:52), [frontend/pwa-install.js](/C:/git/NURA/frontend/pwa-install.js:67)

### [СРЕДНЕ] Личный кабинет PWA открывает несуществующий web-route отчёта

## Не проверено / нет доступа
- Полный интерактивный браузерный прогон с кликами, `Console` и `Network`: локальный browser runtime не поднялся из-за Windows sandbox error `CreateProcessAsUserW failed: 5`.
- Реальные `/app/*` на проде: в текущем окружении не удалось отдельно открыть их как живые страницы, поэтому PWA-блок частично проверен по текущему фронтовому коду и роутам.
- Telegram deep-link / login / Mini App внутри Telegram: нет тестового Telegram-аккаунта и не было живого доступа к клиенту Telegram.
- End-to-end оплата и post-payment flow: не проводился реальный платёж.
- Push-уведомления и фактическая доставка Web Push: не проверялись end-to-end.
- Адаптивность desktop / tablet / mobile по живому DOM: не проверялась инструментально из-за отказа браузерной автоматизации.
