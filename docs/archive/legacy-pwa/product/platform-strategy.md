## 1. Контекст и обоснование

NURA работает на двух платформах: **PWA** (`nura-ai.ru`) и **Telegram-бот** (`@nura_bot`).

До июня 2026 бот был основным интерфейсом продукта. Это решение принималось в условиях:
- быстрого MVP без необходимости делать мобильное приложение
- органического трафика через Telegram-каналы

К июню 2026 контекст изменился:
- РКН активно замедляет трафик Telegram, блокировки усиливаются
- Веб-воронка (`mini.html`) уже реализована и работает
- PWA позволяет полностью независить от экосистем App Store / Google Play / Telegram
- Web Push через APNs и FCM неуязвим для блокировок РКН

**Принятое решение (ADR-001):** PWA — ядро продукта. Telegram-бот — канал привлечения и push-fallback.

## 2. Роли платформ

### 2.1 Главный принцип

У каждой функции есть **один дом**. Дублирование функции на обе платформы создаёт путаницу для пользователя и лишнюю работу для разработчика.

> Правило: если пользователь может сделать что-то в PWA — он делает это в PWA.
> Бот предлагает это действие через ссылку в PWA, а не реализует сам.

### 2.2 PWA — что делает

| Функция | Описание | Статус |
|---------|----------|--------|
| Мини-анализ | Форма с датой рождения, бесплатный результат | ✅ Готово |
| Покупка матрицы 890₽ | YooKassa redirect прямо со страницы | ✅ Готово |
| Полный HTML-отчёт | 17+ секций, доступ навсегда по ссылке | ✅ Готово |
| Покупка таро-подписки 390₽/мес | YooKassa через веб | 🔨 Нужна разработка |
| Таро-расклады | Все 7 раскладов в интерфейсе приложения | 🔨 Нужна разработка |
| Чат с NURA | AI-диалог на основе матрицы пользователя | 🔨 Нужна разработка |
| Профиль | История покупок, отчёты, управление подпиской | 🔨 Нужна разработка |
| Управление уведомлениями | Выбор канала: Web Push или Telegram | 🔨 Нужна разработка |
| Установка на экран | manifest.json + Service Worker | 🔨 Нужна разработка |
| Web Push | Карта дня, напоминания через APNs/FCM | 🔨 Нужна разработка |
| Поделиться отчётом | Web Share API — нативный диалог шера | 🔨 Нужна разработка |

### 2.3 PWA — что НЕ делает

- Не реализует виральный share внутри Telegram (пересылка сообщений — нативная функция TG)
- Не отправляет пуши через серверы Telegram
- Не является отдельным сайтом — это тот же домен `nura-ai.ru`

### 2.4 Telegram-бот — что делает

| Функция | Описание | Статус |
|---------|----------|--------|
| Мини-разбор | Первый контакт: дата → архетип → 5 блоков бесплатно | ✅ Готово |
| Deep-link в PWA | После каждого ключевого действия — ссылка с auth-токеном | ✅ Частично |
| Push-fallback | Карта дня для тех, кто не установил PWA или iOS < 16.4 | ✅ Готово |
| Виральный share совместимости | Карточка-картинка, реферальная ссылка, обратный шер | 🔨 Спринт 1 |
| Связка с PWA-аккаунтом | Принять link-токен, объединить аккаунты | 🔨 Нужна разработка |

### 2.5 Telegram-бот — что НЕ делает

- Не является основным интерфейсом для работы с продуктом
- Не принимает оплату подписки 390₽/мес (только ссылку на PWA)
- Не показывает полный отчёт (только кнопку "Открыть в NURA")
- Не ведёт полноценный чат с NURA (максимум 3-5 сообщений → CTA в PWA)
- Не хранит историю пользователя (только ссылается на PWA)

## 3. Источники трафика

### 3.1 Все внешние источники → лендинг nura-ai.ru

```
TikTok / Instagram / Threads
    │
    └──► nura-ai.ru (лендинг + мини-анализ + PWA)
              │
              ├── Мини-анализ бесплатно
              ├── Покупка матрицы 890₽
              └── CTA: установить PWA / перейти в бота

Яндекс Директ / SEO
    │
    └──► nura-ai.ru

Telegram-канал / виральный share
    │
    └──► @nura_bot (бот) ──► deep-link в PWA
         или
    └──► nura-ai.ru
```

### 3.2 Почему не ведём напрямую в бота из соцсетей

- Лендинг не зависит от Telegram и работает при любых блокировках
- На лендинге есть мини-анализ прямо в браузере — конверсия выше, нет лишнего перехода
- После мини-анализа пользователь может сразу купить или установить PWA

### 3.3 Роль Telegram-канала

Telegram-канал — отдельный органический источник. Ведёт:
- В бота (для мини-разбора и виральных механик)
- На лендинг (для покупки и установки PWA)

## 4. Пути пользователя

### 4.1 Путь через соцсети (основной)

```
1. Видео в TikTok / Instagram / Reels
2. Переход по ссылке в био → nura-ai.ru
3. Вводит дату рождения → мини-анализ в браузере (бесплатно)
4. Видит CTA → покупает матрицу 890₽ → YooKassa → /report/{token}
5. Читает отчёт → видит предложение "Установить NURA"
6. Устанавливает PWA на экран
7. Разрешает Web Push → карта дня каждое утро
8. Оформляет таро-подписку 390₽/мес в PWA
```

Telegram в этом пути **не участвует вообще** на шагах 1-8.

### 4.2 Путь через Telegram

```
1. Переходит в @nura_bot из канала или по реферальной ссылке
2. /start → мини-разбор в боте (бесплатно)
3. CTA "Открыть в NURA" → deep-link в PWA с auth-токеном
4. Попадает в PWA уже авторизованным
5. Покупает матрицу или подписку в PWA
6. Устанавливает PWA, разрешает Web Push
7. Бот продолжает слать push-fallback если PWA не установлена
```

### 4.3 Путь через Яндекс Директ

```
1. Клик по объявлению → nura-ai.ru (или mini.html)
2. Мини-анализ → покупка матрицы
3. После покупки → предложение установить PWA
```

Этот путь полностью веб, никакого Telegram.

## 5. Связка аккаунтов PWA ↔ Telegram (ADR-003)

Пользователь не обязан подключать Telegram. Это добровольный шаг, который открывает дополнительные возможности.

### 5.1 Три точки входа в Telegram из PWA

**Точка 1 — После расклада совместимости**

Самый естественный момент. Под результатом расклада две кнопки:
- `📤 Поделиться в Telegram` → открывает `tg://msg_url?url=...&text=...` с карточкой и реферальной ссылкой
- `🔗 Скопировать ссылку` → для тех у кого нет Telegram (Web Share API fallback)

**Точка 2 — Профиль → Уведомления**

В настройках уведомлений:
```
Как получать карту дня:
○ Web Push — прямо на экран телефона  [рекомендуется]
○ Telegram-бот — в мессенджере
```
При выборе Telegram → кнопка "Подключить" → запускает link-механику.

**Точка 3 — Однократный баннер после первой покупки**

Показывается один раз снизу экрана после оплаты матрицы:
> "Есть Telegram? Там можно делиться совместимостью с друзьями."

Кнопка "Подключить" и крестик "Закрыть навсегда". Больше не показывается.

### 5.2 Механика link-токена

```
1. PWA генерирует UUID-токен
2. Сохраняет в Redis: link_token:{TOKEN} → user_id (TTL 15 минут)
3. Показывает пользователю ссылку: t.me/nura_bot?start=link_{TOKEN}
4. Пользователь нажимает → открывается бот
5. Бот получает /start link_{TOKEN}
6. Бот ищет токен в Redis → находит user_id
7. Проставляет telegram_id в запись пользователя в БД
8. Бот отправляет: "✅ Аккаунты связаны. Карта дня теперь придёт сюда."
9. Токен удаляется из Redis
```

### 5.3 После связки

- Аккаунты объединены: один User в БД с заполненными `web_session_id` и `telegram_id`
- Система применяет правило дедупликации уведомлений (см. раздел 6)
- Пользователь может управлять каналом уведомлений в профиле PWA

## 6. Уведомления и дедупликация (ADR-002)

### 6.1 Главное правило

> Пользователь никогда не получает одно уведомление дважды — ни в PWA Push, ни в Telegram.

### 6.2 Логика выбора канала

```python
# Celery задача send_daily_card
if user.has_pwa_push:
    send_web_push(user)          # через APNs / FCM
else:
    send_telegram_message(user)  # через @nura_bot
```

### 6.3 Таблица сегментов

| Сегмент | Условие | Канал уведомлений |
|---------|---------|-------------------|
| A | PWA установлена, Web Push разрешён | Web Push (APNs/FCM) |
| B | PWA установлена, Web Push не разрешён | Telegram-бот |
| C | PWA не установлена, есть Telegram | Telegram-бот |
| D | PWA не установлена, нет Telegram | ❌ Уведомления недоступны |

### 6.4 Реализация в БД

Новое поле в таблице `users`:
```sql
has_pwa_push BOOLEAN NOT NULL DEFAULT FALSE
```

Устанавливается в `True` когда:
- Пользователь разрешил Web Push в браузере
- Подписка успешно сохранена через `POST /api/push/subscribe`

Сбрасывается в `False` когда:
- Пользователь отозвал разрешение на уведомления
- Push-подписка истекла или стала невалидной (ошибка 410 от APNs/FCM)

### 6.5 Устойчивость к блокировкам

Web Push идёт через серверы Apple (APNs) и Google (FCM). РКН не может заблокировать их без отключения push-уведомлений у всех банков, маркетплейсов и приложений в стране. Это делает Web Push устойчивым каналом связи независимо от судьбы Telegram.

## 7. Устойчивость к блокировкам Telegram

### 7.1 Что происходит при полной блокировке Telegram

| Компонент | Статус при блокировке |
|-----------|----------------------|
| Лендинг nura-ai.ru | ✅ Работает |
| Покупка матрицы через веб | ✅ Работает |
| Полный отчёт /report/{token} | ✅ Работает |
| PWA для установивших | ✅ Работает |
| Web Push уведомления | ✅ Работает |
| Таро, чат, профиль в PWA | ✅ Работает |
| Telegram-бот | ❌ Недоступен |
| Виральные механики через TG | ❌ Недоступны |
| Трафик из TG-канала | ❌ Недоступен |

### 7.2 Вывод

Блокировка Telegram = потеря одного из каналов привлечения, но не потеря продукта. Все платящие пользователи с установленной PWA не заметят разницы. Новые пользователи приходят через SEO, Яндекс Директ, Instagram и другие каналы напрямую на лендинг.

## 8. Правила для разработки

Любой разработчик или AI-агент, работающий с кодом NURA, должен соблюдать следующие правила:

### 8.1 Оплата

- Оплата матрицы 890₽ — только через `POST /api/v1/web/create-payment` (веб)
- Оплата подписки 390₽/мес — только через `POST /api/v1/web/subscribe` (веб, нужна разработка)
- Бот **не создаёт платежи**, только отправляет ссылку на PWA

> Исключение: существующий `buy_matrix` handler в боте остаётся как legacy до тех пор, пока PWA-оплата не протестирована в проде. После тестирования — убрать.

### 8.2 Отчёты

- Полный отчёт открывается только по ссылке `/report/{token}` в браузере/PWA
- Бот отправляет кнопку "📄 Открыть отчёт" с URL, а не рендерит содержимое

### 8.3 Deep-link из бота

После любого значимого действия в боте (мини-разбор, покупка, привязка аккаунта) бот **обязательно** показывает кнопку перехода в PWA:

```
┌─────────────────────────────────┐
│ 🌐 Открыть в NURA               │  ← URL: nura-ai.ru/?token=AUTH_TOKEN
├─────────────────────────────────┤
│ 🏠 В меню                       │
└─────────────────────────────────┘
```

Auth-токен позволяет войти в PWA без повторного ввода данных.

### 8.4 Push-уведомления

- Перед отправкой уведомления всегда проверять `user.has_pwa_push`
- Никогда не дублировать одно событие на оба канала
- При ошибке Web Push → автоматически fallback в Telegram (если `telegram_id` есть)

### 8.5 Новые функции

При проектировании новой функции задавать вопрос:
> "Это нужно пользователю в моменте быстрого взаимодействия (бот) или при глубокой работе с продуктом (PWA)?"

Быстрое взаимодействие → бот. Глубокая работа → PWA.

## 9. Технический план реализации PWA

### Приоритет 0 — Минимум для установки (~19 часов)

| Задача | Файл | Часов |
|--------|------|-------|
| manifest.json | `/manifest.json` | 2 |
| Service Worker (push + кэш) | `/service-worker.js` | 4 |
| iOS meta-теги | `<head>` всех страниц | 1 |
| Иконки 192×192 и 512×512 | `/icons/` | 1 |
| Install UI: Android auto-prompt | JS в `mini.html` / `index.html` | 2 |
| Install UI: iOS инструкция с GIF | модальное окно | 2 |
| Web Push backend (VAPID, `/api/push/subscribe`) | `api/routes/push.py` | 6 |
| Поле `has_pwa_push` + Alembic миграция | `core/models.py` + `alembic/` | 1 |

### Приоритет 1 — Продуктовые экраны (~40 часов)

Отдельные страницы в рамках `nura-ai.ru`:
- `/app` — главный экран PWA (матрица, навигация)
- `/app/tarot` — раздел таро
- `/app/chat` — чат с NURA
- `/app/profile` — профиль и управление

Все с нижним таббаром, без адресной строки в standalone-режиме.

### Приоритет 2 — Интеграция с ботом (~8 часов)

- Эндпоинт `POST /api/v1/web/link-telegram` (генерация link-токена)
- Бот-хендлер для `start=link_{TOKEN}`
- Кнопка "Поделиться в Telegram" (Web Share API + tg:// fallback)
- Баннер после покупки (однократный)
