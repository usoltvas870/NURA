# Документация NURA

Единый источник правды для продукта, инженерных решений и процессов разработки NURA — AI-продукта самопознания на основе Матрицы Судьбы.

Документация разделена на два домена: **Engineering** (как это работает) и **Product** (зачем это нужно и как выглядит). Структура унаследована от Astro Insight и адаптируется под NURA.

## Структура

### `/engineering`
Техническая документация по архитектуре, коду, инфраструктуре и данным.

* `architecture.md` — концептуальный дизайн, слои и инварианты системы.
* `tech-stack.md` — стек технологий (Python 3.11, FastAPI, aiogram, SQLAlchemy 2.0, Celery, Redis, PostgreSQL 16).
* `core-domain.md` — ядро системы: Matrix of Destiny calculation, DeepSeek AI-движок.
* `data-model.md` — структура БД PostgreSQL (users, reports, payments).
* `api-auth.md` — авторизация Telegram, вебхуки.
* `operations.md` — эксплуатация, деплой, docker-compose.
* `developer-guide.md` — стандарты кода, Ruff, pytest.
* `technical-debt.md` — известный техдолг и баги.
* `/platforms/` — спецификации платформ (telegram-bot, web).
* `/admin/` — админ-панель (TODO).

### `/product`
Продуктовое видение, UX/UI и контент.

* `vision.md` — миссия NURA, модель продукта.
* `platform-matrix.md` — матрица фичей по платформам (Telegram / Web).
* `brand-identity.md` — тон коммуникации NURA (тёплый, без эзотерики).
* `glossary.md` — терминология (архетипы, арканы, матрица).
* `/features/` — описания модулей (мини-разбор, полный отчёт, совместимость, инсайты, чат).
* `/ui-ux/` — чертежи интерфейсов отчётов, спецификации UX.
* `/monetization/` — ценообразование, пейволлы, подписка 390₽/мес.
* `/engagement/` — ежедневные инсайты, ретеншн-механики.
* `/content/` — промпты для AI, редакционная политика.

## Источник истины
- **`Nura PRD.txt`** — канонический документ требований (корень проекта).
- **`AGENTS.md`** — правила для AI-агентов.
- Если код расходится с документацией — код исправляется под доку, не наоборот.

## Правила работы с документацией
1. **Единый источник правды:** Если функционала нет в документации — его не существует в продуктовом смысле.
2. **Точность и плотность:** Без абстракций. Конкретные схемы, протоколы, реализации.
3. **Строгое разделение:** Инженерное и продуктовое не смешивать.
4. **Актуальность:** При каждом значительном изменении обновлять docs.
