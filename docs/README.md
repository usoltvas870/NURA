# Документация NURA

Единый источник правды для продукта и разработки NURA — AI-проводника самопознания через Матрицу Судьбы и Таро-ритуалы.

> **Текущее состояние проекта** — всегда в `STATE.md` (корень репозитория).
> **Последнее обновление документации** — 09.06.2026 (Сессия 18).

---

## Как читать этот индекс

Перед началом работы над любой задачей — прочитай документы в таком порядке:

1. `STATE.md` — что сейчас готово и что блокирует
2. `platform-strategy.md` — как устроена архитектура платформ (PWA + Telegram)
3. Специфический документ для твоей задачи (см. таблицы ниже)

## Источник истины — приоритеты

При конфликте между документами:

```
1. Код на VPS (продакшн) — что фактически работает
2. STATE.md — текущие статусы и блокеры
3. platform-strategy.md — архитектурные решения (ADRs)
4. Специфический документ задачи (bot-spec, pwa-spec, report-spec...)
5. Остальные документы
```

**Код всегда приоритетнее документации.** Если расходятся — проверяй код.

## Правила работы с документацией

1. **После каждой сессии** — обновить `STATE.md`: статусы, блокеры, запись в историю
2. **Устаревший документ** — пометить `⚠️ Устарел` в этой таблице, не удалять без явного решения
3. **Новый документ** — добавить строку в таблицу выше и в карту зависимостей
4. **Цены** — единственный источник правды: `pricing.md`. Везде остальное — следствие
5. **Архитектурные решения** — фиксировать в `platform-strategy.md` как ADR с датой
6. **PWA-задачи** — сверяться с `pwa-spec.md` перед реализацией
7. **Бот-задачи** — читать `bot-spec.md` + `bot-spec-pwa-patch.md` вместе
